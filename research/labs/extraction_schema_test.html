Verdict. The shape of the schema is right — the highest-value fields (compute-contract terms, published prices, licences, benchmark deltas) extracted cleanly and would have produced real signal. But four fields are being asked to do a job extraction cannot do, and they fail in the direction that matters: silently, with confident wrong values.

D1 is_public is wrong more often than right — and it is not extraction's job critical

Across 14 counterparty judgements the model got 6 right:

Z.ai             → is_public: false   ✗ listed SEHK 2513
xAI              → is_public: false   ✗ inside SpaceX, Nasdaq SPCX
SpaceX           → is_public: false   ✗ listed Nasdaq SPCX since 2026-06-12
Caisse des Dépôts → is_public: true    ✗ French state institution, not listed
LangChain        → is_public: true    ✗ private
Harvey           → is_public: true    ✗ private
Databricks       → is_public: true    ✗ private
OpenAI           → is_public: true    ✗ private
Boston Dynamics  → is_public: true    ✗ Hyundai subsidiary
ASML, Capgemini, CMA CGM, Amadeus, Box, Apptronik → correct

The document never states whether a company is listed. The model is answering from its own knowledge — exactly the thing that must not happen — and it is wrong at the precise point that decides whether an event reaches a ticker.

Fix: is_public and ticker are never extracted. Extraction answers "what does this document say"; a deterministic registry lookup keyed on entity name answers "what is this entity". Two layers, and mixing them injects error at the highest-leverage step. This is the F10 three-class registry earning its place on evidence.

D2 Dates are invented critical

  • Mistral sovereign post → "2024-08-11". Actual: 2026-08-11. A two-year error.
  • Gemini 3.7 Flash → "2026-08-13"; the index gave only "August 2026" with no day.
  • Gemini Robotics ER 2 → "2026-07-30"; index gave only "July 2026".

A wrong year silently breaks the rolling 3-month window, the freshness filter and the ingestion watermark — and nothing errors.

Fix: date comes from feed metadata / HTTP headers / URL slug, never from the model. If no machine-readable date exists, the item is dated null and quarantined — not guessed.

D3 event_type as a single label drops signal critical

The Mistral sovereign post is simultaneously a product launch (Regional Endpoints), a model release (OCR 4, Medium 3.5, Small 4, Voxtral TTS) and an infrastructure commitment (1 GW by 2030). It was tagged product_launch — so the 1 GW capacity signal has no event type carrying it, and only survived because power_mw happened to catch it.

Fix: event_types[], multi-label. An article is not one thing.

D4 "funding" means two opposite things critical

The Anthropic wellbeing post — a $5m grant programme Anthropic is giving away — was tagged event_type: funding. In our vocabulary funding means the lab raising capital, which fires lab_capital_formation and reads as a capex-cycle signal.

This is the cleanest false-positive generator in the set: a philanthropy announcement entering the investment renderer as evidence of capital formation. It is also the item I predicted would be inert, and it very nearly wasn't.

Fix: split into funding_raised and funding_granted. Direction of money flow is not a detail.

D5 quoted_span is unstable and drifts to marketing

Same Mistral document, two runs:

run A → "Mistral Regional Endpoints, now generally available, let customers choose
         whether their inference runs in Europe or the US…"
run B → "every enterprise and country must be in control of the models it uses,
         choose where the intelligence runs"

Run B is corporate philosophy, not news. Gemini 3.7 Flash likewise gave "our most intelligent workhorse model yet for coding and agents" rather than the halved price. "The sentence that best states what is new" is underspecified, and the model resolves it toward whatever sounds most like a headline.

Fix: one quoted span per extracted claim, not one per document, and each span must contain the quantity or counterparty it supports. That makes the citation justify the field rather than summarise the vibe — and it fixes citation granularity at the same time.

D6 artifact_availability returns contradictions

Shieldstral   → ["weights", "paper_only"]
DeepSeek-R1   → ["weights", "code", "api", "paper_only"]
Gemini 3.7    → "api"          ← string, not array
Mistral sov.  → "api"          ← string, not array

paper_only is not a member of the same set — it is the absence of the others, so it can never co-occur with weights. The type also flips between string and array.

Fix: four independent booleans — weights_available, code_available, data_available, api_available. No enum, so no contradiction is expressible.

D7 people[] conflates lab staff with quoted outsiders

The Mistral post returned six people — Matan Grinberg (Factory), Luis Maroto (Amadeus), Christophe Fouquet (ASML), Aiman Ezzat (Capgemini), Olivier Sichel (Caisse des Dépôts), Rodolphe Saadé (CMA CGM). None of them work at Mistral. They are customers quoted in testimonials, and they were tagged function: dealmaking and product as though they were staff.

Person-level tracking — the expensive part of the register — would be polluted by every testimonial quote in every product post. Meanwhile the genuinely useful internal people (Tulsee Doshi on Gemini 3.7; Steven Hansen and Peng Xu on Robotics ER 2) came through correctly elsewhere.

Fix: add affiliation: internal | external. Only internal feeds the person register; external is counterparty evidence.

D8 technique_type ignored its enum completely

Specified as training | serving | eval | agentic | tooling. Returned:

"multimodal safety classifier", "regional_inference_infrastructure",
"reinforcement learning in post-training", "large language model",
"wellbeing_evaluation_methodology", ["embodied_reasoning", "video_understanding", …]

Zero of seven returned a valid enum value. A free-text field wearing an enum's clothes is unusable for filtering, and this is the AI-team renderer's main axis.

Fix: constrained decoding or hard post-validation that rejects out-of-enum values rather than passing them through. Per the project's typed-boundaries principle, malformed output must be caught, not trusted.

D9 Ambiguous field names cause bleed

xAI compute deal → "parameters": "300 megawatts from Colossus 1 data center"
                   "power_mw":    300   ← same fact, correct field

parameters reads as "deal parameters" as easily as "model parameters".

Fix: rename to model_parameters. Field names are prompts.

D10 lab is undefined for press sources

The TechCrunch item returned lab: null — correct, TechCrunch is not a lab — but the subjects are Anthropic and xAI, and this was the single most valuable extraction in the set.

Since press is the primary source for compute contracts (F8), a schema that cannot name the subject lab of a press item cannot ingest the highest-value event type.

Fix: split publisher from subject_labs[].

D11 benchmark_deltas has no fixed type

Gemini 3.7   → {"FrontierCode_1_1": "43.6% vs 34.4%", …}   object
Shieldstral  → "matches or outperforms models up to 7x its size"  prose
Robotics ER2 → {"progress_classification_accuracy": "57.4%"}      no baseline
DeepSeek-R1  → null  ← numbers exist, but only inside an image
Fix: benchmark_deltas[] as an array of {benchmark, value, baseline_value, unit}. Prose that will not decompose goes to a separate qualitative_claims[] rather than corrupting a numeric field.

W1 What worked — and it is the part that matters keep

  • Compute-contract terms extracted perfectly. "Anthropic will be paying xAI $1.25 billion per month through May 2029, with a discounted rate for the first two months as xAI completes its ramp-up" — plus 300MW, Colossus 1, and both counterparties with roles. A fully-formed lab_compute_contract from one pass.
  • Published prices, cleanly. Gemini 3.7 Flash: 0.75 / 3.75 with price_change: "50% reduction vs Gemini 3.6 Flash". DeepSeek-R1: 0.55 / 2.19. inference_cost_down is arithmetic, as F4 argued.
  • Licences, cleanly. Apache 2.0 (Shieldstral), MIT (DeepSeek-R1) — the AI team's decisive field.
  • Structured benchmark deltas on the one document that published them as text.
  • The noise control stayed inert on every field except event_type (see D4): no counterparties, no artifacts, no prices.

Propagation test — the corrected model, end to end

The most valuable extraction in the set names zero BIT holdings. Under the old rule (drop anything without a held ticker) it would have been discarded. Traced through mechanisms instead:

Event — TechCrunch, 2026-05-20. "Anthropic will be paying xAI $1.25 billion per month through May 2029"; 300MW from Colossus 1.
Anthropic (private)→ xAI / SpaceX (SPCX — not held)→ lab_compute_contract+ training_compute_up+ datacenter_power_up
reaches → Micron 7.75% TSMC 4.38% Marvell 4.21% IREN 8.92% TeraWulf 1.94% Riot 0.53% HUT8 1.01%

A 300MW, three-year lab compute contract validates the neocloud business model that IREN, TeraWulf, Riot and HUT8 sell, and pulls through to memory and foundry on training demand. Roughly 29% of the book, from a document that mentions none of it.

This is the F3 correction demonstrated on a real document. The old "resolve to a held ticker or drop" rule would have thrown away the single highest-value item in the sample. Entity class is an attribute; the mechanism is the road.

Schema v2

Every change below is forced by a numbered defect above — nothing speculative.

core:
  publisher                  ← split from lab (D10)
  subject_labs[]             ← new (D10)
  event_types[]              ← multi-label (D3); funding split (D4)
  date                       ← from feed metadata, NEVER extracted (D2)
  claims[]:                  ← replaces one span per doc (D5)
    text
    quoted_span              ← must contain the quantity/counterparty it supports
  people[]:
    name, role, function     ← research|dealmaking|policy|product
    affiliation              ← internal|external, new (D7)
  counterparties[]:
    name, relationship
    entity_class             ← resolved by registry lookup, not extracted (D1)
    is_public, ticker        ← registry lookup only (D1)
  quantities:
    currency_amount, currency_direction   ← in|out (D4)
    power_mw, duration
    model_parameters         ← renamed (D9)
    price_per_1m_input, price_per_1m_output, price_change
    benchmark_deltas[]: {benchmark, value, baseline_value, unit}   ← typed (D11)
  qualitative_claims[]       ← prose that will not decompose (D11)
  weights_available, code_available, data_available, api_available  ← booleans (D6)
  licence
  technique_type             ← enum, hard-validated, reject on miss (D8)
The structural lesson. Four defects (D1, D2, D10, and half of D11) share one cause: the schema asked the extractor for facts that are not in the document. Whether a company is listed, what date a page was published, what a benchmark's baseline was — these are lookups and metadata, not reading comprehension. Every time the boundary was crossed, the model answered confidently and wrongly.

The rule that falls out: extraction may only be asked "what does this text say". Anything else is a registry, a feed header, or a computation.
