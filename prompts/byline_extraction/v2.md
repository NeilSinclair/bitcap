# Byline extraction — v2

**Task.** Extract the byline of one research article or paper from its HTML, for any
lab, not just Anthropic.
**Used by.** `research/papers/llm_byline.py::extract_page`, called with a `lab_label`.
**Diff from v1.** `research/papers/README.md` records the v1 spike's finding: the
deterministic parser beats the LLM wherever a lab's markup is known, and the LLM's role
is a fallback for pages the parser can't read. v1 hardcoded that fallback to Anthropic —
`is_anthropic`, and a default affiliation of `["Anthropic"]` when the page states none.
Extending the papers leg to DeepMind, Meta and Mistral found none of them has affiliation
markup a deterministic parser could rely on (confirmed live: DeepMind's arXiv HTML says
"Google", not "Google DeepMind", or nothing at all; Meta's says "Meta Superintelligence
Labs" on some papers and nothing on others; Mistral's carries no affiliation markup at
all) — so for these labs the LLM path is the *primary* extractor, not a rare fallback,
and needs to work for any lab, not just one. `is_anthropic` becomes `is_lab_staff`; the
default-affiliation string is interpolated from `{lab_label}` rather than hardcoded, so a
lab's public name changing (already observed: Meta AI → Meta Superintelligence Labs) is a
config edit, never a prompt edit.

---

## System

You extract bylines from research-article HTML. You return only what the document
states. You never infer an author, an affiliation, or a date that is not written in the
page.

## User

Below is the HTML of a research article published by **{lab_label}**. Extract its
byline.

Return, in the order the page lists them:

- `authors` — one entry per person credited as an author of this article.
  - `name` — the person's name, with any superscript or symbol marker removed.
  - `affiliations` — the organisation(s) this article attributes to that person. If the
    page uses numbered superscripts, resolve them through the page's own footnote
    legend. If the page states a single affiliation for all authors, use it for all. If
    the page states none, use `["{lab_label}"]`.
  - `marks` — the symbol markers attached to this author (`*`, `†`, `‡`, …), if any,
    excluding the numeric affiliation keys.
  - `is_fellow` — true if this article presents the person as a fellow, resident,
    intern, or visiting participant in a programme, rather than as a member of staff.
  - `is_lab_staff` — true only if this article presents the person as employed by
    **{lab_label}**. A fellowship, residency, internship or collaboration is not
    employment. If the page states an affiliation string that is visibly a variant or
    sub-unit of {lab_label} (for example a named internal team or lab division), treat
    that as {lab_label} employment — but a *different* organisation entirely, even one
    that collaborates with {lab_label}, is not.
- `date` — the publication date the page states, as `YYYY-MM-DD`. `null` if the page
  states none.
- `star_means` — what this page's own footnotes say the `*` marker denotes:
  `core` (core contributor), `equal` (equal contribution), `fellows` (a fellows or
  residency programme), `other` (defined as something else), or `null` (not used or
  not defined on this page).
- `order_meaningful` — false if the page states the author order is alphabetical or
  otherwise not a credit ordering; true otherwise.
- `no_byline` — true if this page credits no authors at all.

Rules:

1. Only authors of **this** article. Names in the body text, in citations, in
   acknowledgements, or in correspondence footers are not authors.
2. Resolve each superscript against the legend printed on this page. Do not carry over
   a convention from any other page.
3. A name broken across a line break is one person, not two.
4. If you cannot find a byline, set `no_byline` to true and return an empty author list.
   Do not guess from the body text.
5. Do not use outside knowledge of {lab_label}'s org chart, team names, or naming
   conventions to decide `is_lab_staff` or resolve an ambiguous affiliation string. Read
   only what this page states.
