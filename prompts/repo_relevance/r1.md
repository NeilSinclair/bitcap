You are filtering GitHub repositories for an intelligence product that tracks
**large language models and the frontier labs that build them**.

Decide whether releases from this repository are on-topic for that product.

You are given the organisation, repository name, star count, primary language,
topics and description. Judge the repository as a whole, not any single release.

## Answer `true` (relevant)

The repository's subject is language models, or the systems that build, run,
evaluate or connect to them:

- model weights, model implementations, or a model's reference code
- training, fine-tuning, inference, serving, quantisation, attention or
  transformer kernels, tokenisers
- agent frameworks, coding agents, prompt tooling, developer tools whose subject
  is a language model
- benchmarks, evaluation harnesses, red-teaming, watermarking, interpretability,
  alignment tooling
- **an official client library, CLI, API definition or worked-example collection
  for a lab's own model API — always `true`.** These are thin and routine, and they are where a
  new model identifier first appears in public.
- general numerical, array or deep-learning infrastructure that language-model
  work is built on: autodiff and optimiser libraries, neural network frameworks,
  vector search and retrieval, distributed training

## Answer `false` (off-topic)

The repository's subject is a different field, however good the work:

- AI or machine learning in another domain: computer vision, image or video
  generation and segmentation, speech and audio, physics simulation, robotics,
  reinforcement-learning environments and agents, game playing, protein
  structure and genomics, materials, weather and climate, mathematics and
  theorem proving
- anything not about AI: web infrastructure, marketplaces, data processing,
  corporate or programme pages

## How to decide the hard cases

**Ask what the repository is *about*, not what it could be used for.** Almost any
numerical library can be used to train a language model. Answer `true` for
general infrastructure only when a language-model stack is genuinely built out of
it. If the repository is built for a specific non-language domain, answer
`false` — even when the technique is shared.

**Multimodal work follows its centre of gravity.** A model whose subject is
language, and which also accepts images, is relevant. A model whose subject is
images, video or audio is not, even if it has a text interface.

**A grab-bag repository is judged on its stated purpose.** If the description
says it collects work across many projects and no single subject dominates,
answer `false`.

**When the description is empty**, judge from the organisation, the repository
name, the language and the topics, and say so in your reason.

Give `reason` as one sentence naming the evidence you used. It is shown to a
human deciding whether the filter can be trusted, so name what you saw rather
than restating the verdict.
